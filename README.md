# طعم الشرق 🍽️ — نظام المنيو الإلكتروني للمطاعم

نظام متكامل (Node.js + Express) لمنيو مطعم بالعربية: **منيو للزوار عبر رمز QR** + **لوحة تحكم كاملة** لإدارة الفئات والأطباق والأسعار والصور والطاولات.

- 🪟 **RTL بالكامل** — تصميم عربي أنيق يعمل على الجوال والحاسب.
- 🔳 **QR لكل طاولة** — رابط مثل `/menu/1?table=3` مع رمز QR جاهز للطباعة (PNG أو طباعة مباشرة).
- 🛠️ **لوحة تحكم** — إضافة/تعديل/حذف الفئات والأطباق، رفع الصور، إخفاء طبق أو فئة بضغطة، تغيير كلمة المرور وبيانات المطعم.
- 🔐 **أمان** — كلمات مرور مشفّرة (bcrypt) + توكن JWT لمدة 24 ساعة + حماية من محاولات تخمين كلمة المرور.
- 🔍 **بحث فوري** في المنيو + تنقّل بين الفئات.
- 👁️ **وضع معاينة** لصاحب المطعم يرى فيه الأطباق المخفية قبل نشرها.
- 🗄️ **MySQL/ MariaDB** كمحرّك أساسي، مع **بديل تلقائي بـ SQLite** ليعمل المشروع فوراً حتى بدون خادم قاعدة بيانات.

## ١) التشغيل السريع

```bash
npm install
cp .env.example .env      # عدّل القيم عند الحاجة
npm run init-db           # إنشاء الجداول + بيانات مطعم تجريبي
npm start
```

ثم افتح:

| الصفحة | الرابط |
| --- | --- |
| الصفحة الرئيسية | http://localhost:3000/ |
| منيو مطعم تجريبي | http://localhost:3000/menu/1 |
| منيو طاولة رقم ٣ | http://localhost:3000/menu/1?table=3 |
| لوحة التحكم | http://localhost:3000/admin.html |

> **كلمة مرور لوحة التحكم الافتراضية: `admin123`** — غيّرها فوراً من «الإعدادات ← تغيير كلمة المرور».

للتطوير مع إعادة التشغيل التلقائي: `npm run dev` — ولإعادة بناء قاعدة البيانات من الصفر: `npm run init-db -- --force`.

## ٢) قاعدة البيانات

### الوضع الافتراضي: `DB_CLIENT=auto`
يحاول النظام الاتصال بـ MySQL، وإن لم يتوفر الخادم ينتقل تلقائياً إلى قاعدة **SQLite** مدمجة في `data/sharq_taste.db` (تُنشأ وتُهيّأ تلقائياً). بهذه الطريقة يعمل المشروع مباشرة على أي جهاز.

| القيمة | السلوك |
| --- | --- |
| `auto` | MySQL إن توفّر، وإلا SQLite *(الافتراضي)* |
| `mysql` | MySQL فقط، ويفشل بخطأ عربي واضح إن لم يتوفر |
| `sqlite` | SQLite فقط |

### تشغيل MySQL يدوياً
```bash
mysql -u root -p < database/mysql/schema.sql
mysql -u root -p < database/mysql/seed.sql
```
ثم اضبط في `.env`:
```env
DB_CLIENT=mysql
DB_HOST=localhost
DB_USER=root
DB_PASSWORD=كلمة_المرور
DB_NAME=sharq_taste
```
أو اترك `DB_CLIENT=auto` وسيتولى `npm run init-db` إنشاء القاعدة والجداول والبيانات تلقائياً (يُنشئ القاعدة إن لم توجد، ويجري التهيئة مرة واحدة فقط).

> ملفات SQL تعتمد `utf8mb4` و `utf8mb4_unicode_ci` — ضروري لتخزين النصوص العربية بشكل صحيح (بدونها تظهر `?????`).
> بصمة كلمة المرور في `seed.sql` مكتوبة كـ `:ADMIN_HASH` ويستبدلها النظام ببصمة bcrypt حقيقية أثناء التهيئة (كلمة المرور: `admin123`، أو ما تضبطه في `DEFAULT_ADMIN_PASSWORD`).

### بنية الجداول
| الجدول | الوصف |
| --- | --- |
| `restaurants` | بيانات المطعم + `admin_password_hash` (bcrypt) |
| `tables` | طاولات المطعم؛ حقل `qr_code` يخزّن **مسار** رابط المنيو (`/menu/1?table=3`) ويُبنى الرابط المطلق وقت العرض |
| `categories` | فئات المنيو + `display_order` + `is_visible` (إظهار/إخفاء الفئة) |
| `menu_items` | الأطباق + السعر + الصورة + `available` (متاح/غير متاح) + الترتيب |

جميع العلاقات `ON DELETE CASCADE`: حذف المطعم يحذف طاولاته وفئاته وأطباقه.

## ٣) واجهات API

### عامة (بدون تسجيل دخول)
| الطريقة | المسار | الوصف |
| --- | --- | --- |
| GET | `/api/health` | حالة الخادم ومحرّك قاعدة البيانات |
| GET | `/api/menu/:restaurantId` | منيو الزائر: المطعم + الفئات + الأطباق المتاحة فقط |
| GET | `/api/menu/:restaurantId?table=3` | نفس ما سبق مع تحديد رقم الطاولة |
| GET | `/api/menu/:id/qr?table=3` | `{ url, qr }` — رمز QR كصورة Data URL |
| GET | `/api/menu/:id/qr?table=3&format=png` | ملف PNG جاهز للطباعة |

**وضع المعاينة:** `GET /api/menu/1?preview=1` مع ترويسة `Authorization: Bearer <token>` يُظهر الفئات والأطباق المخفية (لصاحب المطعم فقط).

### الإدارة (تحتاج `Authorization: Bearer <token>`)
| الطريقة | المسار | الوصف |
| --- | --- | --- |
| POST | `/api/admin/login` | `{ password, restaurantId? }` → `{ token, restaurant }` |
| GET | `/api/admin/me` | بيانات المطعم الحالي |
| GET/PUT | `/api/admin/restaurant` | قراءة/تحديث بيانات المطعم (يقبل `multipart` لرفع الشعار) |
| PUT | `/api/admin/password` | تغيير كلمة المرور |
| GET | `/api/admin/stats` | إحصائيات اللوحة |
| GET/POST | `/api/admin/categories` | عرض/إضافة فئة |
| PUT/DELETE | `/api/admin/categories/:id` | تعديل/حذف فئة (حذف الفئة يحذف أطباقها) |
| GET | `/api/admin/menu` | الفئات مع أطباقها (يشمل غير المتاح) |
| POST | `/api/admin/menu-items` | إضافة طبق — `multipart/form-data` مع حقل `image` |
| PUT/DELETE | `/api/admin/menu-items/:id` | تعديل/حذف طبق |
| GET/POST | `/api/admin/tables` | عرض الطاولات مع روابط QR / إضافة طاولة |
| DELETE | `/api/admin/tables/:id` | حذف طاولة |

مثال:
```bash
TOKEN=$(curl -s -X POST localhost:3000/api/admin/login \
  -H 'Content-Type: application/json' \
  -d '{"password":"admin123"}' | node -pe "JSON.parse(require('fs').readFileSync(0)).token")

curl -X POST localhost:3000/api/admin/menu-items \
  -H "Authorization: Bearer $TOKEN" \
  -F "categoryId=1" -F "name=طاجين لحم" -F "price=65.5" -F "image=@dish.jpg"
```

## ٤) سير العمل في لوحة التحكم

1. **الفئات**: «المنيو ← إضافة فئة» (مثال: مقبلات، أطباق رئيسية، حلويات، مشروبات).
2. **الأطباق**: زر «➕ طبق» داخل كل فئة — الاسم، الوصف، السعر، الصورة (حتى 5MB)، الترتيب، والإتاحة.
3. **الإتاحة**: مفتاح «متاح» في كل صف يخفي الطبق فوراً من منيو الزوار دون حذفه.
4. **الطاولات**: «الطاولات و QR ← رقم الطاولة ← إضافة» — ثم **نسخ الرابط** أو **طباعة** بطاقة QR للصقها على الطاولة.
5. **الإعدادات**: اسم المطعم، الوصف، العملة، الهاتف، البريد، العنوان، الشعار، وكلمة المرور.

## ٥) هيكل المشروع

```
server.js                  نقطة التشغيل (Express + الملفات الثابتة + معالج الأخطاء)
src/
  db.js                    طبقة قاعدة البيانات الموحّدة (MySQL ⇄ SQLite + التهيئة الأولية)
  routes/public.js         API الزوار + توليد QR
  routes/admin.js          API الإدارة (تسجيل دخول، منيو، طاولات، إعدادات)
  middleware/auth.js       JWT (تحقق إلزامي/اختياري)
  middleware/upload.js     رفع صور الأطباق والشعار + حذف الصور القديمة
  utils/                   تحقق المدخلات، بُناة QR، مساعدات العنوان والأخطاء
database/
  mysql/{schema,seed}.sql  سكربتات MySQL كاملة (utf8mb4)
  sqlite/{schema,seed}.sql نسخة SQLite مطابقة
public/
  index.html               الصفحة الرئيسية التعريفية
  menu.html                منيو الزائر
  admin.html               لوحة التحكم
  css/style.css            نظام التصميم (RTL)
  js/{common,menu,admin}.js
  images/                  صور الأطباق التجريبية
scripts/init-db.js         تهيئة/إعادة بناء قاعدة البيانات
tests/api.test.js          اختبارات واجهة الـ API (npm test)
uploads/                   الصور المرفوعة من لوحة التحكم
```

## ٧) النشر على الإنترنت

```env
NODE_ENV=production
PORT=3000
SECRET_KEY=سلسلة-عشوائية-طويلة-فريدة      # إلزامي: بدونه تظهر تحذيرات ويمكن تزوير التوكنات
BASE_URL=https://menu.example.com          # يُستخدم في روابط QR المطبوعة
DB_CLIENT=mysql
```
- إن لم تضبط `BASE_URL`، يُبنى رابط QR من عنوان الطلب نفسه (يدعم `X-Forwarded-Host/Proto` خلف Nginx أو Cloudflare).
- مثال تشغيل دائم:
  ```bash
  npm i -g pm2
  pm2 start server.js --name sharq-taste
  pm2 save
  ```
- تأكد من صلاحيات الكتابة لمجلدي `uploads/` و `data/` عند استخدام SQLite.

## ٨) ملاحظات مهمة حول سكربتات SQL الأصلية

عدّلت هذه النسخة بعض التفاصيل لتكون جاهزة للتشغيل الفعلي:

| الملاحظة | السبب |
| --- | --- |
| بصمة كلمة المرور `$2b$10$abc123...` لم تكن بصمة bcrypt صالحة | لم يكن الدخول ممكنًا بها إطلاقاً؛ الآن تُولَّد بصمة حقيقية عند التهيئة |
| أُضيف `utf8mb4` و `utf8mb4_unicode_ci` لكل الجداول | بدونها يفشل تخزين النص العربي أو تظهر رموز `?` |
| `image_url` أصبح `VARCHAR(500)` وأُضيف عمود `is_visible` للفئات | لاستيعاب الروابط الخارجية وإخفاء فئة كاملة |
| حقل `qr_code` يخزّن مساراً نسبياً (`/menu/1?table=3`) بدل رابط مثبّت | الرابط المطلق يُبنى وقت العرض فيبقى صحيحاً عند تغيير الدومين، ويُولَّد رمز QR عند الطلب (كان يُخزَّن كصورة Base64 ضخمة قبل ذلك) |
| أُضيفت تحققات للمدخلات وفهارس المفاتيح الأجنبية | حماية من السعر السالب والنصوص الطويلة والتكرار |

## ٩) حل المشاكل

| المشكلة | الحل |
| --- | --- |
| `تعذّر الاتصال بـ MySQL` | شغّل خدمة MySQL أو استخدم `DB_CLIENT=sqlite` للعمل محلياً |
| النص العربي يظهر `?????` في MySQL | القاعدة أو الأعمدة ليست `utf8mb4` — أعد التنفيذ بـ `database/mysql/schema.sql` |
| `لا يمكن تسجيل الدخول` | كلمة المرور الافتراضية `admin123`؛ إن غيّرتها ولم تتذكرها نفّذ `npm run init-db -- --force` |
| روابط QR تشير إلى `localhost` | اضبط `BASE_URL` بعنوان الموقع الحقيقي ثم أعد توليد/طباعة البطاقات |
| الصور لا تظهر بعد الرفع | تأكد من صلاحيات الكتابة لمجلد `uploads/` |
